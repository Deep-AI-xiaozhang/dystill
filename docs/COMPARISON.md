# 和现成方案比：蒸馏工坊差在哪、不差在哪

> 这一页只比较**核对链路的设计取舍**，不评价任何具体项目的整体优劣。
> 比较对象是几类公开思路的代表做法（通用视频总结、claimify 式声明抽取、guard 式外部检索核查），
> 不是逐行对比某个仓库。所有「我们这样做」都附带代价；没有免费的正确性。

## 1. 四类方案速览

| 类型 | 典型产物 | 证据从哪来 | 主要短板 |
|---|---|---|---|
| 通用视频总结 / 转写工具 | 摘要、章节、逐字稿 | 视频本身 | 不逐条回查；结论对错无从定位 |
| claimify 式声明抽取流水线 | 结构化声明 + 判定 | 原素材或外部语料 | 三阶段全交模型，漂移与成本高 |
| guard / RAG 事实核查 | 事实性判断 | 检索网页、百科、知识库 | 核的是「网上对不对」，不是「原片有没有」 |
| **蒸馏工坊** | 一份 Markdown 笔记 + 逐条核对报告 | **只用原素材内部**（转写 + 画面 + 时间戳） | 不判「客观真假」；有假 ❌；平台范围窄 |

一句话：前三类回答的问题各不相同，本工具回答的是**「笔记里的话，在原视频里找不找得到出处」**。
这不是「事实真相」问题，而是「笔记有没有脱离原片」问题。

## 2. 逐层对比（事实框架来自 ROADMAP「F2 的自研取舍」）

| 层 | 现成方案常见做法 | 我们怎么做 | 为什么 / 代价 |
|---|---|---|---|
| **L1 选择** | claimify 三阶段全交模型 | **规则做选择**（分节 / 跳过观点概括 / 「无」项）+ 模型只做消歧与分解，且**默认关**（`pipeline.check_l1_disambiguate`，D24） | 选择是产品边界问题，规则可复现；模型漂移会让基准集无法对比。代价：规则可能漏掉一些值得核的声明 |
| **L2 证据** | guard 检索网页 / Wikipedia | **只用原素材内部**（转写 + 画面 + timecodes）；打分 = 字面 n-gram 覆盖度 **+ 硬事实命中检测** | 核对的是「笔记 vs 原视频」，不是「这话在网上对不对」。代价：原片没讲清楚的内容，无法靠外部知识补齐 |
| **L3 闸门** | 模型判定即结论 | **四道确定性闸门，只把 ✅ 往下压**：① 零证据不许判一致；② 声明里的数字在原素材里 0 命中不许判一致；③ 声明的对外/商业措辞在原素材里 0 命中不许判一致；④ 深度模式覆盖度阈值 | 最致命的失败是**假 ✅**（让用户不再回看原片）。四道闸不花钱、可复现。代价：会把更多条目压成 ⚠️，报告更「吵」 |
| **长笔记覆盖** | 全量核对或直接截断 | 超上限**按章节轮转取样**（head 截断会让「数据基准 / 对你的启发」整节 0 覆盖；轮转后每节都有） | 「核了多少」必须等于「覆盖了哪些」，不能是「只核了前几节」。代价：超长笔记仍然不是全量核对 |
| **❌ 改写** | 报告里给建议，或直接改 | 默认只给建议，`--rewrite` 显式开启才动笔记；原句逐字命中才替换，修正建议含幻觉数字/专名则不落盘 | 静默改写会破坏「笔记 vs 原片」的可信度。代价：用户需要自己决定是否回改 |

## 3. 和通用视频总结工具比

| 维度 | 通用总结工具 | 蒸馏工坊 |
|---|---|---|
| 产物 | 摘要 / 章节 / 逐字稿 | 结构化 Markdown 笔记（结论、口播要点、画面要点、知识要点） |
| 证据 | 通常不逐条给 | 每条声明尽量给时间戳与证据原文 |
| 核对 | 一般没有 | 四层核对 + 逐条报告 + 顶部徽章 |
| 改写 | 直接生成 | 默认不改写，`--rewrite` 才动 |
| 平台 | 广 | **抖音优先**；本地视频/音频/图文帖；B 站可选 |

如果你要的是「十分钟看完一个视频」，通用总结工具更直接。
如果你要的是「以后还能回查、能带走、能知道自己哪里可能记错」，本工具才有意义。

## 4. 和 claimify 式声明抽取比

- claimify 式流水线的核心是**三阶段都交模型**：选择、消歧、分解。
- 我们把**选择**收回规则层：分节、跳过纯观点概括、跳过「无」项；模型只负责消歧与分解，而且默认关闭。
- 原因不是「模型不行」，而是**基准要能对比**：模型改写声明集合后，两轮结果不可直接比条数（D41 实测 68 vs 97）。
- 代价：规则是产品边界，换题材/换语言时可能需要调整；纯观点类视频能核的声明会变少。

## 5. 和 guard / RAG 事实核查比

- guard 式方案检索外部网页或知识库，回答「这句话在世界上对不对」。
- 我们**只检索原素材内部**：转写、画面 OCR/描述、时间戳。原因是产品问题不同——
  用户要的是「我的笔记有没有歪曲这个视频」，不是「这个视频说的对不对」。
- 好处：不需要外网检索、不受搜索结果质量影响、证据可逐字回查。
- 代价：**不判客观真假**。视频本身说错了，核对不会纠正；原片没展开的内容，核对也不会补。

## 6. 我们刻意不做的事

1. **不做去水印 / DRM 破解 / 登录绕过 / 付费内容解锁**——没有这类功能，也不接受这类需求。
2. **不把下载器塞进仓库**——抖音下载由第三方 `douyin-downloader`（MIT）完成，风险与合规由使用者判断。
3. **不联网判断「这话对不对」**——L2 只用原素材内部证据。
4. **不静默改写笔记**——默认只报告；`--rewrite` 是显式动作。
5. **不预设内容分类体系**——知识库的主题词从用户自己的笔记内容统计（D39）。
6. **不宣称「核对准确率 X%」**——验收数字是内部留出集、不可复现，且 v2 阈值是事后调整（见 BENCHMARK）。

## 7. 什么时候适合 / 不适合

**适合**：

- 抖音口播 / 教程 / 图文帖，想要一份能回查的结构化笔记；
- 在意「笔记有没有编造」，愿意接受 ⚠️/❌ 噪音并人工回看；
- 本地优先、笔记要进 Obsidian、模型想用免费通道或本地 ollama；
- 能接受「抖音优先、B 站可选」的平台范围。

**不适合**：

- 需要联网事实核查（「这个说法在世界上对不对」）；
- 需要全平台批量搬运、去水印、下载受保护内容；
- 要求 100% 判定准确、不愿意人工回看；
- 需要逐字稿级转录（本工具产物是笔记，不是字幕文件）。

## 8. 代价清单（写给自己看，也写给用户看）

- **假 ❌ 噪音**：三个免费判定模型都有（D41–D43）；❌ 是回看信号，不是结论。
- **假 ✅ 残留**：四道闸门只能压低，不能消除；验收数字里仍有 6~8 条。
- **单次不可复现**：同模型两次可差 7.5pp（D8/D10），任何单次跑分只能当区间。
- **平台范围窄**：抖音优先；B 站要装可选依赖；其他平台没有承诺。
- **下载依赖第三方**：上游行为变化会影响抖音链接路径；本地文件模式不受影响。
- **免费通道限流**：TPM/RPM 限制、偶发空正文、日级降级窗口；判定链建议至少两家（D21/D40）。
- **基准不可复现**：历史验收 CSV 未入库且已丢失；换环境只能建自己的新基准。

## 9. 结论

本工具不是「更好的通用视频总结器」，也不是「更准的联网事实核查器」。
它选的是一条更窄的路：**抖音优先、本地优先、证据只在原素材内部、判定只往下压、改写必须显式。**

这条路换来的是「笔记可回查、失败模式可解释、数据留在本机」；
代价是「平台窄、有假 ❌、不判客观真假、基准不可复现」。
如果你要的正是前者，它合适；如果你要的是后者，现成方案可能更合适。
