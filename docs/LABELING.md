# 人工标注口径 v1（基准集的尺子的尺子）

> 谁用：给核对引擎做人工标注的人（也就是你）。`bench_check.py` 的一切"准确率"
> 都以 `human_verdict` 为真值——**标注错了，引擎修得再好分也是假的**（D9 的教训：
> "70% 的分母本身不可靠"；D10 的教训：首批 40 条里争议 5 条复核后全是标注侧有理）。
> 所以这份文档和 DECISIONS 同级：改口径必须在此留记录。
>
> 对应遗留问题：遗留问题 #1「核对'事实点'标准」由本文档第 2、3 节关闭。

## 0 · 三条铁律

1. **人是真值，AI 只能当草稿。** `bench/label_once.py` 那种"模型先标、人抽检"只许用于
   预填；凡进入验收分母的条目，`human_verdict` 必须经手过人（抽检 ≠ 全检，验收分母要全检）。
2. **盲标：先写你的判定，后看引擎的判定。** `claims.csv` 里没有引擎结果，保持这样；
   生成抽检表（`make_spotcheck.py`）后才允许并排看——顺序反了就是抄作业。
3. **回看原片是标注的一部分，不是可选项。** 拿不准就拖到 `evidence_ts` 时间点听原句，
   10 秒钟的事；凭 CSV 里截断的 evidence 猜，就是在生产 D10 那种假 ❌。
   **但只有要判 `ok` / `mismatch` 时才必须回片**——判 `doubt`（素材不足）靠转写即可，
   因为"素材不足以确认"本身就是结论。回片是为了给 `ok`/`mismatch` 找出处和反向引文，
   不是每个条目的固定开销。

## 1 · 标注文件与命名

- 每个视频一份：`bench/claims_<记录目录名>.csv`（如 `claims_aweme_7678xxxx.csv`），
  由 `python scripts/make_bench.py data/<记录目录> -o bench/claims_<记录目录名>.csv` 生成。
- 验收时合并所有已标注 CSV 一起喂 `bench_check.py`（它按 `key` 列分组跑引擎，天然支持多视频）。
- 字段：`claim`=待判的声明句；`section`=笔记栏目；`evidence_ts`/`evidence`=检索侧给的证据
  （**只作参考，不许当依据**——L2 有已知的"同主题不同工具"天花板，D10）；
  `human_verdict`=你填 ok / mismatch / doubt；`human_note`=你填的判定依据（非 ok 必填）。

## 2 · 三值判据（背下来，不要现场发挥）

| verdict | 判 | 一句话标准 |
|---|---|---|
| `ok` | 一致 | **原视频里找得到出处**：话说过、字亮过、数字对得上——哪怕换了说法 |
| `mismatch` | 不一致 | **能引出一句与该声明相反或明确矛盾的原话**（见下方硬门槛） |
| `doubt` | 存疑 | 素材不足以确认，**或**证据疑似来自另一主体/另一工具/作者的推论升格 |

### ⛔ mismatch 硬门槛：必须给出「反向引文」

`human_note` 里必须引出原片（转写/画面）中**与这条声明相反或明确矛盾的那一句**。
**引不出来 → 只能判 `ok` 或 `doubt`，不许判 `mismatch`。**

这是 v1.1 新增的唯一硬门槛，目的是让判定**可机械复现**：任何复核者拿到同一条，
都能靠"有没有反向引文"得到同一个结论，不再依赖标注当时的状态（D28 的教训）。

**为什么必须是引文、不能是"我觉得不对"**——三条已被 D28 证伪的错判长这样：

- **拿自己的猜测当标尺**：人标 note 猜了一个看起来合理的金额，转写原文却是差两个数量级的另一种读法。
  拿这条 note 去核对笔记，等于自己判自己。**正解本身没被原片证实过，就不能当依据。**
- **拿"更好的概括"当矛盾**：笔记写「输光了」，原话是「拉拉扯扯有输有赢」。
  这不是矛盾，是概括——按 §2「概括/换说法是允许的」，`ok`。
- **口径写了但没执行**：§3 标题就写着"ASR 噪声不是笔记的错"，遇到噪声却判了 `mismatch`。
  **发现缺口时的默认动作是改判 `doubt`，不是"维持"**——维持才是不做判断。

### 分界纪律（与引擎同一套，D5/D9/D10 逐条搬过来的）：

- **"我看到的片段里没有" ≠ "原视频没有"** → 一律 `doubt`，不许 `mismatch`。
  `mismatch` 的门槛是"正面撞上矛盾"。
- **推理性升格按 `doubt`**：笔记把"作者自己在用"写成"对外提供服务/可接单变现"，
  即使硬事实全对 → `doubt`（D9 那条经典病例）。
- **同主题不同工具按 `doubt`**：证据段落讲的是 A 工具、声明说的是 B 工具
  （典型：多款工具做同一件事的测评视频）→ `doubt`，不是 `mismatch`（D10 纪律 10）。
- **概括/换说法是允许的**：笔记是总结，意思到位、素材支持 → `ok`，
  不因"没逐字出现"判 `doubt`。
- **观点、建议、情绪句**：理论上 L1 已跳过；若仍出现在 CSV 里，标 `doubt`
  并在 `human_note` 写"不该进核对"——这是给 L1 的反馈信号，攒着。

## 3 · 中文口播特有规则（ASR 噪声不是笔记的错）

1. **同音/近音按音近处理**：千万=通义千问、质普=ZCode、codes=Codex、occa=Orca。
   笔记写了正确名而转写听错了 → `ok`，不是 mismatch。
2. **数字口播与写法差异要归一**：三点八 max ↔ 3.8 max、两千 ↔ 2000。
   只有**数值本身不符**才 `mismatch`（200 vs 2000）。
3. **专名以画面为准**：转写没听清的工具名/人名，若抽帧里以文字出现过（`vlm.txt` / frames），
   按画面证据判。
4. **栏目名是上下文**："测试任务：找到下载目标栏并上传"里"测试任务"表明这是**要做的事**
   不是**已发生的事**——判 ok/doubt 时先带上栏目语义（D10 bug 2 的标注侧镜像）。
5. **笔记忠实转写了 ASR 的错误数字/单位 → `doubt`，不是 `mismatch`**（v1.1 补）**：
   这是笔记没有的错。**转写本身自相矛盾（同一数字前后两种读法）同样按 `doubt`：
   两种读法都是噪声，谁也没被证实。**判 `mismatch` 需要先有一条不含噪声的反向引文。**
6. **主体错配 → `doubt`**（v1.1 补）：把**提问者、路人、他人**说的话记成当事人
   （该句是提问者说的，不是当事人在评价他人）。

## 4 · 一条声明的标准操作流程（60~90 秒）

1. 读 `claim` + `section`，弄清它在断言什么（数字？因果？做过没？谁说的？）。
2. 在转写 `transcript.txt` 里搜关键词（工具名/数字/动词），找作者原话。
3. 找到候选句 → 看 `[]` 时间戳，**拖原片听那 10 秒**；找到候选画面 → 开 `frames/` 对应图。
4. 下判定，填 `human_verdict`；非 ok 必填 `human_note`（写"哪里矛盾/缺什么"，
   将来复盘全靠它）。
5. 全程不看引擎结果。
6. 实在拿不准 → `doubt` + note 写"待复核"，**不硬猜**。

## 5 · 标注质量自检（防止尺子自己是弯的）

- **隔日重标 10 条**：完成一批后随机抽 10 条，次日不看旧标注重标一遍，
  自一致率 <90% 说明口径没吃透或口径本身有歧义 → 回到本文档改规则（并在文末变更区记一行）。
- **⚠️ 标注漂移是连续标注的产物，别连着标完一个视频**（v1.1，D28 教训）：
  D28 复核 58 条连标的视频时，13 条 mismatch 里只有 1 条站得住，尺子是在标的过程中变的。
  做法：**每个视频标 15~20 条就换视频**，全部标完再回头补；换段之后回头重看，
  尺子才有机会被察觉。
- **拿不准时别替笔记改写得更合理**：标注问的是"原片有没有这句话"，
  不是"这句话是不是更好的总结"。
- **争议条目双视角**：与引擎分歧大的条目（`make_spotcheck.py` 自动挑），
  按 D10 流程"先看片段属于哪款工具/哪个人物，再看内容"——只看内容会冤枉引擎。
- **分母门槛**：一个视频的 CSV 只有在"全部条目人工标注 + 自检抽 5 条复查通过"后，
  才许并进验收。验收报告里注明每份 CSV 的标注状态。
