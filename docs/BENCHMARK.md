# 核对基准与验收口径

> 这一页记录核对引擎的验收方法、历史数字与诚实边界。
> 先给结论：内部留出集三轮 **97.5% / 97.5% / 96.6%**，按 v2 口径达标；但**这批数据不可复现**，
> 基准 CSV 从未入库、当前副本也已丢失。请不要把它当成「可复跑的公开基准」。

## 0. 一页结论

- **数字**：294 条声明 / 4 个视频 / 独立跑三轮；引擎标 ✅ 的内容真对率 = 97.5% / 97.5% / 96.6%。
- **口径**：v2 = 引擎标 ✅ 的内容真对率 ≥ 95%，取最差一轮；最差 96.6% → 达标（D44）。
- **性质**：这是**项目内部留出集**，且仓库内视频都参与过迭代，**不宜当作严格泛化能力**。
- **可复现性**：**不可复现**。基准 CSV 从未进入仓库，当前工作副本也已丢失；`bench/` 目录本身被 `.gitignore` 排除。
- **假 ❌**：三个免费判定模型都会产生假 ❌（D41–D43）；**❌ 只能当「值得回看原片」的信号**，不是「确认有错」。
- **阈值来源**：v2 的 95% 是 2026-10-15 **事后调整**的验收口径，**不是预注册**（D44）。

## 1. 为什么单独写一页

README 只保留摘要，避免把「一次内部评测」写成产品承诺。这一页保留完整口径、命令和历史数字，
方便后来的人核对「当时到底按什么标准算通过」，也方便明确哪些结论**不能**引用。

## 2. 口径演变：v1.1 → v2

两个口径量的是**同一批 6~8 条错**，只是分母不同：

| 口径 | 算式（留出集第 1 轮） | 结果 | 判定 |
|---|---|---|---|
| v1.1：假阳性率（分母 = 全部声明） | 6 ÷ 294 | 2.04% | ❌ 未达 ≤1% 硬线 |
| v2：引擎标 ✅ 的内容真对率 | 231 ÷ 237 | 97.5% | ✅ 达 ≥95% 线 |

- v1.1 的硬线是「假阳性 ≤ 1%」，三轮实测 2.04% / 2.04% / 2.72%，一直判「未通过」，为此投入了多轮治理。
- 2026-10-15 用户拍板：「笔记正确率已经 95% 以上，质量可以了，不用治假阳性了。」（D44）
- 新口径 v2：**引擎标 ✅ 的内容真对率 ≥ 95%**（取最差一轮）。
- **必须写清楚**：这是**事后调整**，不是预注册阈值。原「假阳性 ≤1%」硬线已关闭，不是「原本就达标」。
- 关闭的还有：D26/D29 的留出集标注待办、L3 第五道闸门（加闸门只会把更多 ✅ 压成 ⚠️，D36 已实证是净亏）。

## 3. 留出集实测数字

运行日期按仓库记录为 **2026-10-04**；口径 v2 于 **2026-10-15** 由用户确认（D44）。

| 轮次 | 引擎标 ✅ 条数 | 其中人判真对 | ✅ 真对率 | 假阳性 | 假阳性率（分母 294） |
|---|---:|---:|---:|---:|---:|
| 1 | 237 | 231 | 97.5% | 6 | 2.04% |
| 2 | 240 | 234 | 97.5% | 6 | 2.04% |
| 3 | 232 | 224 | **96.6%** | 8 | 2.72% |

- 总声明数 294，视频数 4，独立判定三轮，模式 `standard`。
- 聚合规则：**硬线取最差一轮**，不取平均（D23）。原因：假阳性是稳定复现的系统性错误，平均会放过它。
- 单次跑分不可当结论：实测同一基准两次可差 7.5pp（D8/D10），所以只看三轮里的最差值。

### 3.1 这组数字不能怎么用

- 不能说「可复现」：输入 CSV 已丢失，仓库里没有对应的 `bench/claims_*.csv`。
- 不能说「准确率 97.5%」：这是**引擎判 ✅ 的条目里人判真对的比例**，不是召回率，也不是全部声明的正确率。
- 不能说「泛化能力 97.5%」：这是内部留出集，仓库内视频参与过迭代，量到的仍偏向 in-sample。
- 不能拿它当宣传口径：D44 明确要求，若将来对外宣称「核对准确率 X%」，必须先按 D26 建全新留出集。

## 5. 基准怎么建（可复现的是方法，不是这批数字）

基准要求：**≥ 50 条声明、≥ 3 个不同题材视频**，人工标注为真值，盲标，回看原片。

```bash
# 1) 导出待标注声明（不调模型，不花 token）
python scripts/make_bench.py data/aweme_xxx -o bench/claims_aweme_xxx.csv

# 2) 生成浏览器盲标工作表（不显示引擎判定，导出即回填 CSV）
python scripts/make_label_sheet.py bench/claims_aweme_xxx.csv

# 3) 按 docs/LABELING.md 的口径 v1 填 human_verdict：ok / mismatch / doubt
#    人标为真值、盲标、回看原片；标完用页面右上角「导出填好的 CSV」覆盖回原文件

# 4) 独立跑三轮判定
python scripts/bench_check.py bench/claims_*.csv --json-out bench/run1.json
python scripts/bench_check.py bench/claims_*.csv --json-out bench/run2.json
python scripts/bench_check.py bench/claims_*.csv --json-out bench/run3.json

# 5) 三轮聚合：硬线取最差一轮（口径 v1.1，D23）
python scripts/bench_summary.py bench/run1.json bench/run2.json bench/run3.json
```

- `bench_check.py --from-json <check.json>` 可以复用已有判定、不重新调用模型，适合先跑通流程。
- 报告与 `--json-out` 摘要都只是中间产物；`bench/` 默认不入库。

## 6. 留出集纪律（D26）

同一批视频既用来定义假阳性、又用来验证改动，量到的是 in-sample，不是泛化能力。所以：

- **任何**提示词或判定规则改动（不只是提示词），验证都必须走**新留出集**。
- 新留出集 = 新视频全程未参与过任何迭代 × 新鲜蒸馏 × 新鲜人工标注。
- 前提检查：新视频的 aweme id 不得出现在已有 `bench/claims_*.csv` 里。
- 标注要求：≥3 个新视频且 ≥50 条；与定义过假阳性的视频**不得重叠**。
- **留出集一旦用来判定某次改动，这一集就烧掉了**：测完必须再取新链接建下一批，否则第二次改动又是 in-sample。

## 7. 标注工作表怎么用

`make_label_sheet.py` 生成的是一份自包含 HTML，浏览器打开即用：

- 表里**只有**【声明 + 栏目 + 时间戳 + 参考证据】，**绝不显示引擎判定**（盲标，防抄作业）。
- **▶ 原片 01:12**：点一下在新标签页打开本地 mp4 并跳到该时刻；时间戳缺失时自动降级为纯文本，不给假链接。
- **快捷键**：`j`/`↓` 下一条、`k`/`↑` 上一条、`1` 一致 / `2` 不一致 / `3` 存疑、`Shift+J` 打开当前条原片。
- **进度自动存草稿**（localStorage，不回写 CSV）：刷新或误关都不丢；真值以导出的 CSV 为准。
- 标完点右上角**导出填好的 CSV**，覆盖回 `bench/` 下同名文件即可。

## 8. 已知失败模式（比数字更重要）

### 8.1 假 ❌（判定说矛盾，实际没错）

免费判定模型都会产生假 ❌（D41–D43 有逐条回看记录），差别只是多少：

| 判定模型 | 观察 | 出处 |
|---|---|---|
| `agnes-3.0-flash` | 同一篇笔记连续两轮，❌ 从 0 涨到 3；逐条回帧核实 **2 条是假 ❌** | D41 |
| `agnes-3.0-flash` | 3 条新视频 666 条声明，判 22 条 ❌，回素材核实**约 10 条是假 ❌** | D42 |
| `agnes-2.5-flash` | 同批 A/B 判 30 条 ❌（比 3.0 多）；出现「拿同一字符串跟自己比」等明显误判 | D43 |

典型误判：证据里明明有「女娲.skill」大字却判「未出现」；证据里出现 4 次的数字判「未找到」；
自己写着「可判 ok」仍然判 mismatch；自己写着「不构成矛盾」仍然判 mismatch。
**实务结论：❌ = 需要人工回看，不是确认有错。** 若嫌核对吵，可调小 `check_max_claims`
（如每篇只核 40 条）。

### 8.2 假 ✅（判定说一致，实际错了）

这是更危险的失败模式：假 ✅ 会让用户不再回看原片。当前用四道**确定性闸门**只把 ✅ 往下压：

1. 零证据不许判一致；
2. 声明里的数字在原素材里查不到不许判一致；
3. 声明的对外/商业措辞在原素材里查不到不许判一致；
4. 深度模式下字面证据覆盖度不达标不判一致。

四道闸门不花钱、可复现，但**不能消除**假 ✅。验收数字里的 6~8 条假阳性就是残留。

### 8.3 其他已知边界

- 转写错误不在核对范围内：核对基于转写文本，ASR 听错会导致证据本身有误。
- 概括准确性不在核对范围内：核对只保证「原片里找得到出处」，不保证「概括得准」。
- L1 声明集合可能跨轮漂移：`check_l1_disambiguate: true` 时模型会改写/拆分声明，
  两轮结果不可直接比条数（D41）；默认关闭。
- 单次结果不稳定：同一模型两次可差 7.5pp，任何单次数字都只能当区间看（D8/D10）。

## 9. 怎么引用这些数字

如果确实要引用，请连同限定语一起引用：

> 内部留出集，294 条声明、4 个视频、独立三轮，引擎标 ✅ 的内容真对率为 97.5% / 97.5% / 96.6%；
> 数据未随仓库发布，不可复现，且不构成泛化能力证明。

不要写成：

- ❌「核对准确率 97.5%」（缺分母与指标定义）
- ❌「可复现的 97.5% 基准」（输入已丢失）
- ❌「留出集泛化能力 97.5%」（内部留出集 + 视频参与过迭代）
- ❌「达到预注册的 95% 阈值」（v2 是事后调整）
