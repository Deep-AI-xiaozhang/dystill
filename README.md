# 蒸馏工坊 (Dystill)

> 抖音优先的本地视频蒸馏工具：把视频、音频、图文帖蒸馏成「不瞎编、可回查、能带走」的 Markdown 笔记，并做笔记级事实核对。B 站是可选依赖。

![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)
![Python 3.10+](https://img.shields.io/badge/Python-3.10%2B-blue.svg)
![本地优先](https://img.shields.io/badge/%E6%9C%AC%E5%9C%B0%E4%BC%98%E5%85%88-offline--first-green.svg)

## 它是什么

输入一条抖音链接、一个本地视频/音频文件，或一篇抖音图文帖，输出**一份本地 Markdown 笔记**。笔记里的每条结论都尽量回原素材找证据：✅ 有出处 / ⚠️ 存疑 / ❌ 不一致，附时间戳可回查。

| 素材 | 支持情况 | 说明 |
|---|---|---|
| 抖音链接 | ✅ 主路径 | 下载由第三方项目 `douyin-downloader` 完成，本仓库不含其代码 |
| 本地视频 / 音频 | ✅ | 不依赖任何平台下载器，离线可用 |
| 抖音图文帖 | ✅ | 没有语音轨，逐图理解后生成笔记 |
| B 站链接 | 可选 | 装 `.[bilibili]`（yt-dlp）后可用；不装时给出可行动提示 |

> 产品重心是抖音，不是「全平台视频总结器」。B 站、本地文件是可用路径，但不作为主卖点。

## 它和别人不一样的地方

1. **笔记会自己坦白**——每条结论回原视频找证据：✅ 有出处 / ⚠️ 存疑标注 / ❌ 不一致点名（附时间戳可回查，`--rewrite` 才按证据改写）
2. **核对只用原素材自己的证据**——不联网判断「这话在网上对不对」，只回答「这句话在原视频里有没有出处」；数字、专名、对外措辞有确定性闸门
3. **本地优先**——笔记是本地 Markdown，可直接进 Obsidian；模型随意换（任何 OpenAI 兼容接口），也可以完全离线

## 安装

```bash
git clone <本仓库地址> distill-workshop
cd distill-workshop
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS / Linux: source .venv/bin/activate
pip install -e .               # 核心本体（含切帧依赖 Pillow / scenedetect）
pip install -e '.[local-stt]'  # 可选：本地转写（faster-whisper，自动下载模型，无需 key）
```

> **PyPI 尚未发布**：不要 `pip install dystill`，请以上面的 `pip install -e .` 源码安装为准。
> 需要 Python 3.10+，以及 PATH 中的 `ffmpeg`（切帧 / 分段转写 / 抽音轨）。

另外需要（按需）：

- **抖音下载层**（只在处理抖音链接时需要；本地文件不需要）：

  ```bash
  python scripts/setup_downloader.py     # 拉取 douyin-downloader（MIT, jiji262）到 external/
  ```

  它不进本仓库（第三方项目自带 .git）。脚本会打印该填进 `config.yaml` 的两行；
  凭据文件由你自己改，脚本不碰。手动方式：把
  [`jiji262/douyin-downloader`](https://github.com/jiji262/douyin-downloader) `git clone` 到
  `external/douyin-downloader`，再把 `download.downloader_dir` 指过去。

- **真实浏览器路径**（可选，仅在抖音页面接口返回异常、需要浏览器环境时尝试）：

  ```bash
  pip install -e '.[douyin-browser]'   # 只拉 playwright python 包
  playwright install chromium          # 再下一个浏览器（一次约 130MB）
  ```

  工具会用本地 Chromium 打开页面并读取播放地址；未安装时自动回退到原接口路径，并给出可行动提示。
  该路径是否可用取决于平台页面与你的网络环境，请自行判断并遵守平台规则。

- **B 站下载**（可选，只在给 B 站链接时需要）：

  ```bash
  pip install -e '.[bilibili]'   # yt-dlp；产品定位是抖音优先，故不做硬依赖
  ```

  没装时 B 站链接会报可行动提示（装它或改走本地文件 / 抖音链接），其余路径零影响。

| 通道 | 读图 | 判定 | 备注 |
|---|---|---|---|
| AgnesAI `agnes-3.0-flash` | ✅ | ✅ | 当前主力：写笔记、画面理解、判定 |
| AgnesAI `agnes-2.5-flash` | ✅ | ✅ | 备选；实测假 ❌ 相对更多（D43） |
| 商汤 `sensenova-6.8-flash-lite` | ✅ | ✅ | 能用；注意限流与偶发空正文 |
| 硅基流动 / 魔搭 `DeepSeek-V4-Flash` | ❌ | ✅ | 纯文本写笔记 + 判定，成本为零 |
| 某第三方中转通道（不具名） | ❌ | ✅ | 可能收费；仅作可选通道，不影响免费通道结论 |

> **本页不写死耗时或单次准确率**：这些数字随通道、日期、额度和并发波动，历史上不同时间测出的排序甚至相反（D41 与 D8 的记录就互相矛盾）。
> 换模型前请在本机实测，以你自己的结果为准：
>
> ```bash
> # 读图形态（单图 / 多图）
> python scripts/vlm_probe.py --record data/aweme_xxx --models agnes-3.0-flash \
>   --base https://api.agnes-ai.cn/v1/chat/completions --key-file <你的key文件>
>
> # 判定质量（喂你自己已人工标注的基准 CSV，--dump 可定位假阳性）
> python scripts/model_pick.py --csv bench/claims_xxx.csv --check data/aweme_xxx/check.json \
>   --models agnes-3.0-flash --base https://api.agnes-ai.cn/v1/chat/completions --key-file <你的key文件>
> ```
>
> 唯一稳定的结论只有一条：**`temperature=0` 不代表可复现**。同一模型两次跑同一批声明可差 7.5pp（D8/D10），所以任何单次跑分都只能当区间看。

## 快速开始

```bash
dystill init      # 生成 config.yaml
# 填入 key（或设置环境变量 DISTILL_API_BASE / DISTILL_API_KEY / DISTILL_MODEL）
dystill doctor    # 体检：缺什么、怎么补；agent 可加 --json 解析 NEED_SETUP

dystill run https://v.douyin.com/xxxx/     # 蒸馏：链接 / 本地媒体文件 → 笔记（可批量）
dystill run video.mp4 --check              # 蒸馏完顺手核对

dystill check aweme_7678251600959376681    # 只核对：笔记 vs 原视频（记录目录/笔记/链接都能给）
dystill clean                              # 清理：失败残留目录 + 过期中间产物（加 --apply 才真删）
dystill kb                                 # 知识库：把所有笔记汇总成索引（+ 自检）
```

> 支持三种素材：**视频**（抖音/B站/本地文件）、**纯音频**（后缀不可信，用 ffprobe 复核容器内的流）、
> **图文帖**（抖音图文，逐图理解后生成笔记；没有语音轨，笔记完全依据图片内容）。

> 在支持 skill 的 agent（如 Claude）里使用：安装本 skill 后直接丢链接即可；
> agent 收到 `NEED_SETUP` 会主动向你要 key，两句对话完成配置。

## 核对（本项目的核心差异）

对已蒸馏的记录跑四层核对，产出**核对徽章 + 逐条报告**：

```bash
dystill check <记录目录|笔记文件|抖音链接>  --mode standard [--note 指定笔记] [--rewrite] [--json]
```

| 模式 | 做法 | 用在哪 |
|---|---|---|
| `fast` | 只核数字 / 专名 / 引用（省 token） | 批量处理、低价值视频 |
| `standard`（默认） | 全部原子声明逐条核对 | 日常蒸馏 |
| `deep` | 标准 + 双信号（字面证据覆盖度达标才认 ✅） | 学习/工作关键视频 |

产物写在记录目录里：

- `check.json` —— 逐条判定（含证据原文与时间戳），机器可读
- `check.md` —— 可折叠逐条报告，每条附原片时间戳可回查
- 笔记顶部徽章 —— `✅ 已抽核 12/15 · ⚠️ 2 条存疑`（幂等写入，重复核对不会越插越多）

> 徽章用「**抽核**」而非「已核对」，是刻意的诚实：长笔记超上限时本就只核抽样，
> 且**核对判定并非百分之百可靠**——三个免费判定模型都有假 ❌（把没错的判成不一致，见 D41–D43）。

### 判定结果说明（重要）

| 标记 | 含义 | 可靠性 |
|---|---|---|
| ✅ ok | 证据支持这条声明 | **较可靠**：证据确实支持 |
| ⚠️ doubt | 证据不足以判断（只提到一半、指代不清、片段里找不到） | 可能是真存疑，也可能是检索没找全 |
| ❌ mismatch | **证据明确与声明矛盾** | **必须人工复查**：已回看的样本里约四到五成是误判 |

**关于 ❌ 的提醒**：❌ 不是「已确认错误」，而是「**值得回看原片**」的信号。
实测三个免费判定模型都会产生假 ❌（D41–D43）：把上一段的评价算到下一段主体上、把「证据没明说」当成「证据明确否定」、证据自相矛盾时选错边。
看到 ❌ 后请点开证据和时间戳回原片确认，不要直接把它当结论。

**诚实边界**：核对只保证「笔记里的话在原视频里找得到出处」，**不保证「概括得准」**，不评价观点对错；
核对基于转写文本，转写本身出错不在核对范围内。判定闸门只把 ✅ 往下压，不会把 ⚠️ 抬成 ✅——
四道确定性闸门：**零证据不许判一致** / **声明里的数字在原素材里查不到不许判一致** /
**声明的对外/商业措辞（提供服务、对外、客户、接单、变现…）在原素材里查不到不许判一致** /
深度模式下字面证据覆盖度不达标不判一致。假 ✅ 会让用户不再回看原片，是这类工具最致命的失败模式。

常用调参（`config.yaml` 的 `pipeline`）：

| 参数 | 用途 |
|---|---|
| `vlm_batch_frames` | 每次请求送几帧给画面理解。**默认 1（逐帧），不建议调大**：一次塞多帧会被单次 max_tokens 截断、块间信息互相稀释，且一帧失败=整条画面维度全丢（D7 有实测） |
| `workers` | 画面理解并发路数：质量优先 2 / 速度优先 4 |
| `check_max_claims` | 单篇最多核多少条声明（0=模式默认 fast 40 / standard 120）。超上限时**按章节轮转取样**，保证每节都有覆盖，截断事实写进报告 |
| `check_batch_delay` | 判定批次之间的间隔秒数；免费/低配额通道遇 429 时调大（如 5） |
| `cache_keep_days` | 中间产物保留天数（默认 7）。下载媒体、转写、画面理解、切帧、核对报告都按这个天数清理；**最终每个记录目录只剩 `note.md`**（0=不自动清理） |

被限流打断了不用从头再来：

```bash
dystill check <记录目录> --retry-failed        # 复用上一轮判定，只重判"调用失败"的条目
dystill check <记录目录> --resume             # 复用上一轮全部判定（不调模型，只重建报告/徽章）
```

## 验收摘要（数字不可复现，细节见 docs/BENCHMARK.md）

内部留出集实测：**294 条声明 / 4 个视频 / 独立跑三轮**，引擎标 ✅ 的内容真对率：

| 轮次 | 引擎标 ✅ | 其中人判真对 | ✅ 真对率 |
|---|---:|---:|---:|
| 1 | 237 | 231 | 97.5% |
| 2 | 240 | 234 | 97.5% |
| 3 | 232 | 224 | **96.6%** |

必须同时读的三条边界：

- **数据不可复现**：这是**内部留出集**，基准 CSV **从未入库**，当前副本也已丢失；本页数字只是历史记录，不是可复跑的基准。
- **不是预注册**：v2 的「✅ 真对率 ≥ 95%（取最差一轮）」是 2026-10-15 **事后调整**的验收口径（D44），不是事先注册的阈值；原「假阳性 ≤1%」硬线已关闭。
- **不是泛化能力**：仓库内视频都参与过迭代，即使叫「留出集」也不宜当作严格泛化能力；核对还有假 ❌，❌ 只当回看信号。

方法、口径演变、完整命令与标注流程都在 [`docs/BENCHMARK.md`](docs/BENCHMARK.md)。

## 对比：和现成方案差在哪

不是通用视频总结器，也不是联网事实核查器。逐层差异（声明抽取、证据检索、判定闸门、长笔记覆盖、❌ 改写）
与「刻意不做的事」见 [`docs/COMPARISON.md`](docs/COMPARISON.md)。

一句话版：**L1 用规则做选择、L2 只用原素材证据、L3 用确定性闸门只把 ✅ 往下压、默认不改写笔记。**
设计上的偏离与「何时该重新考虑」记在 [`docs/DECISIONS.md`](docs/DECISIONS.md)，阶段计划在 [`docs/ROADMAP.md`](docs/ROADMAP.md)。

## 知识库：把散落的笔记汇成一张索引

蒸得多了，笔记散在 `data/<记录>/note.md` 里，翻起来费劲。`dystill kb` 把它们汇总成一份
`notes/知识库.md`：类型分组 + 主题簇 + 逐篇一句话 + 全量索引表。

```bash
dystill kb                  # 生成/刷新索引（幂等，重复跑结果一致）
dystill kb --check          # 只自检，不生成
dystill kb --frontmatter    # 顺带给每篇笔记补 type/topic/tags 三个 YAML 字段（供 Obsidian 检索）
dystill kb -o 索引.md        # 自定义输出路径
```

**分类从哪来**：本工具**不预设任何分类表**。索引里的「主题」是从你自己的笔记内容里统计出来的高频词
（标题 + 主题字段），「类型」用的是笔记自己写的 `实操教程 / 观点认知`。所以换任何题材的用户都能用——
工具不替你决定内容该分成哪几类，也不评价内容值不值得看。

**自检报什么**（只报事实，不做价值判断）：

| 级别 | 检查项 |
|---|---|
| ❌ ERROR | 重复笔记（同一身份键出现多次）／空壳笔记（正文过短，疑似生成失败）／失效引用（笔记在、素材目录没了） |
| ⚠️ WARN | 缺身份键或键格式异常／有素材无笔记（蒸馏中断）／索引过期（笔记数 > 索引收录数） |

> 自检只回答「缺件、重复、对不上」，不回答「这条笔记写得好不好」——那是你自己的事。

## 隐私边界：什么数据会去哪

**只留本地的**：笔记（`notes/`）、素材归档（`data/`：转写/帧/画面理解原文）、缓存（`cache/`）、核对报告（`check.json/check.md`）。

**API key**：`config.yaml` 与 key 文件都在你机器上，由 `.gitignore` 排除，不进入仓库。key 只随请求头发给你自己配置的模型平台，不写日志、不发往其他任何地方。
本工具**没有任何遥测/统计/上报代码**——全部网络出口见下方白名单。

**本工具的全部网络出口（白名单，grep 可复现）**：
1. 你在 `config.yaml` 里配置的 LLM/VLM 供应商（`api_base`）——发往这里的：视频转写片段、画面帧截图、笔记声明与证据（AI 功能本身，要处理就得给模型看）
2. 抖音 / B 站——只下载视频（单向拉取），由第三方下载器或 yt-dlp 完成
3. 本机 127.0.0.1（ollama 检测）与 ffmpeg/ffprobe/scenedetect 本地子进程——不出网

**两个如实说明**：
- 下载层 `douyin-downloader` 是第三方项目（MIT）：它对接平台接口的行为由上游决定，介意者可只用本地文件模式（`dystill run <视频文件>`）；
- **想彻底零出网**：用「完全离线」配置——ollama + 本地视觉模型，转写/切帧/笔记/核对全本地，除下载视频外可断网运行。

> **发布快照**：对外发布采用**单一提交（无历史）**的快照，不含任何开发历史提交。
> 当前工作区的 `config.yaml`、`.env`、`*_key.txt` 均已被 `.gitignore` 排除。
